# Claude 데스크탑 프롬프팅 입문
## 초보자를 위한 실전 가이드

> AI한테 "일 잘 시키는 법"을 정리한 문서입니다. Claude 데스크탑 앱을 기준으로, 처음 쓰는 사람도 오늘 당장 써먹을 수 있게 썼어요.
> 컨텍스트 엔지니어링처럼 복잡한 얘기는 뺐습니다. **8가지 기본기 + Claude 데스크탑 전용 기능 + 바로 쓰는 템플릿**.

## 1. 왜 프롬프팅이 기술인가

같은 직원에게 같은 일을 시켜도, **시키는 사람에 따라 결과가 10배 차이** 납니다. AI도 똑같아요. 아니, 더 심해요. AI는 맥락을 짐작하지 않습니다. 여러분이 준 정보만큼만 답합니다.

예시를 볼까요.

**나쁜 프롬프트:**
> "마케팅 카피 써줘."

**좋은 프롬프트:**
> "30대 직장인 여성 대상, 건강기능식품 정기구독 서비스의 인스타그램 광고 카피를 3개 써줘. 각각 한 줄씩, 40자 이내, 구매 유도 CTA 포함, 친근한 반말 톤. '피로회복'이라는 단어는 쓰지 말고 더 구체적인 상황으로 표현."

두 번째가 길어서 귀찮아 보이죠? 하지만 첫 번째로 받은 결과를 "이게 아니고 저게 아니고" 고쳐가며 10번 주고받는 것보다, 처음부터 자세히 쓰고 한두 번에 끝내는 게 **훨씬 빠릅니다.**

프롬프팅은 **"AI의 성능을 끌어올리는 기술"**이 아니라, **"내 머릿속 생각을 상대에게 정확히 전달하는 기술"**이에요. 사실 이건 AI 등장 전에도 인간끼리 필요했던 기술이죠.

## 2. 시작 전에 — Claude 데스크탑의 구조 이해

프롬프팅 원칙 배우기 전에 Claude 데스크탑이 어떻게 생겼는지 한 번 훑고 가요. 몇 가지 기능을 알아두면 프롬프팅도 확 달라집니다.

### 2.1 화면 구성

- **왼쪽 사이드바**: 지난 대화 목록, 프로젝트, 설정
- **중앙**: 대화창 (입력 + Claude 답변)
- **첨부 버튼**: 대화창 왼쪽 아래, 파일 드래그 앤 드롭도 가능
- **상단 모델 선택**: Opus / Sonnet / Haiku 중 고르기

### 2.2 대화(Chat) vs 프로젝트(Project)

- **대화**: 일회성. 새 질문을 위한 새 세션.
- **프로젝트**: 같은 맥락을 공유하는 대화 모음. 공통 지침("이 프로젝트에선 반말로 답해")과 공통 지식 파일(PDF 업로드)을 걸어둘 수 있음.

**언제 뭘 쓰나?**
- 단발성 질문 → 대화
- 반복되는 작업(매주 리포트 쓰기, 특정 주제 브레인스토밍) → 프로젝트

### 2.3 모델 선택 팁

- **Claude Opus** (최상위): 긴 분석, 창의적 글쓰기, 복잡한 추론. 느리고 비쌈.
- **Claude Sonnet** (주력): 일반 작업에 최적. 속도·성능 밸런스.
- **Claude Haiku** (경량): 빠른 간단 질의. 요약·분류·간단 대화.

초보자는 **Sonnet을 기본으로** 두고, 만족스럽지 않을 때 Opus로 올리세요.

## 3. 8가지 핵심 원칙

여기가 이 문서의 심장입니다. 이 8개만 몸에 배면, 프롬프팅 수준이 이미 상위 20%에 들어가요.

### 원칙 1. 역할을 지정하세요

AI에게 "너는 누구야"를 알려주면 답변의 관점과 톤이 확 달라집니다.

**Before:**
> "회의록 잘 쓰는 법 알려줘."

**After:**
> "너는 10년 차 프로덕트 매니저야. 팀 회의록을 잘 쓰는 구체적인 방법과, 팀원들이 읽고 싶어 하는 회의록의 특징을 5가지로 알려줘."

"10년 차 PM"이라는 역할이 붙는 순간, 답변이 이론이 아니라 **현장 감각**으로 바뀝니다.

**자주 쓰는 역할 예시:**
- "너는 30년 경력의 편집자야" → 글 피드백
- "너는 주니어 개발자를 가르치는 멘토야" → 코드 설명
- "너는 소비자 인사이트 전문가야" → 시장 조사 분석
- "너는 친절한 상담사야" → 고민 상담

### 원칙 2. 목표를 명확히 쓰세요

"뭘 만드는 건지"를 AI가 알아야 좋은 답이 나옵니다.

**Before:**
> "이 문서 정리해줘."

**After:**
> "이 문서를 읽고, 우리 팀 주간 미팅에서 5분 안에 전달할 수 있는 3포인트 요약을 만들어줘. 의사결정이 필요한 항목이 있으면 맨 위에."

"이 문서 정리"로는 AI가 요약을 할지, 재구성을 할지, 번역을 할지 모릅니다. **"누가 → 어떤 상황에서 → 무슨 용도로"** 쓸 건지까지 알려주세요.

### 원칙 3. 형식을 지정하세요

어떻게 답해야 하는지 형식을 찍어주면 가독성이 몇 배 올라갑니다.

**형식 지시 예시:**
- "표로 정리해줘, 컬럼은 3개: 이슈 / 원인 / 해결책"
- "불릿 5개, 각 30자 이내"
- "JSON 형식으로, 키는 title/description/priority"
- "마크다운 보고서 형식. 제목 / 요약 / 상세 / 결론 순서"
- "두 가지 옵션의 비교표로"

**실전 팁:** 출력 형식을 답변 안에 샘플로 박아주면 최고예요.

> "이런 포맷으로 써줘:
>
> ```
> 제목: ___
> 대상: ___
> 메시지: ___
> ```"

### 원칙 4. 예시를 보여주세요 (Few-shot)

말로 100번 설명하는 것보다 **예시 하나** 주는 게 훨씬 효과적입니다.

**Before:**
> "사용자 후기를 요약해줘."

**After:**
> "사용자 후기를 요약해줘. 이런 식으로.
>
> 예시:
> 원문: '배송은 빨랐는데 제품 포장이 허술해서 안에 스크래치가 났어요. 환불받고 싶습니다.'
> 요약: [배송 빠름 / 포장 허술 / 제품 손상 / 환불 요청]
>
> 이제 아래 후기를 같은 방식으로 요약해줘:
> \{후기 내용\}"

예시를 **1~3개** 보여주면 AI가 패턴을 정확히 따라합니다. 이걸 "Few-shot Prompting"이라고 해요.

### 원칙 5. 단계별로 생각하게 하세요

복잡한 문제는 AI에게 **"단계별로 풀어"**라고 시키면 정확도가 훨씬 올라갑니다.

**Before:**
> "이 마케팅 전략이 맞는지 판단해줘."

**After:**
> "이 마케팅 전략을 평가해줘. 단계별로:
> 1. 먼저 타겟 고객이 누구로 설정됐는지 정리
> 2. 그 고객의 행동 패턴에 이 전략이 맞는지 분석
> 3. 경쟁사와 차별화 포인트 있는지 검토
> 4. 위 세 개를 종합해서 최종 평가 (A/B/C 등급)"

바로 "이건 A등급이야"라고 답하는 것보다, 단계를 밟게 하면 **근거가 탄탄**해지고, 여러분도 AI의 추론을 검토할 수 있어요.

"step by step으로 생각해줘" 한 마디만 넣어도 성능 오릅니다.

### 원칙 6. 제약을 구체적으로 거세요

길이·톤·금지사항을 명시하세요.

**좋은 제약 예시:**
- "500자 이내, 존댓말"
- "전문용어 쓰지 말고 중학생도 이해하게"
- "불릿 리스트 금지, 문단으로만"
- "한 문단에 3문장 이하"
- "긍정적 표현만 쓰고 '단점'이라는 단어 금지"
- "이모지 쓰지 말 것"

제약은 AI에게 **자유도를 뺏는 게 아니라, 방향을 알려주는 울타리**예요.

### 원칙 7. 맥락을 충분히 주세요

"왜 이게 필요한지"를 알려주면 훨씬 좋은 답이 나옵니다.

**Before:**
> "임원 보고서 써줘."

**After:**
> "다음 주 임원 회의에서 우리 팀 신규 프로젝트 승인을 받아야 해. 임원 3명이 참석하는데, 그중 재무 담당은 ROI를 중시하고, 전략 담당은 장기 비전을 중시해. 이 두 관점 모두 커버하는 10분짜리 보고서를 써줘."

"왜 쓰는지 / 누가 읽는지 / 뭘 얻고 싶은지" 이 세 가지가 맥락의 뼈대입니다.

### 원칙 8. 반복하며 개선하세요

첫 답이 완벽할 일은 거의 없습니다. **대화를 이어가며** 다듬으세요.

**개선 지시 예시:**
- "이거 좋은데, 톤을 더 캐주얼하게"
- "2번 항목은 너무 길어. 절반으로 줄여"
- "다른 관점 2가지도 제시해줘"
- "이 중에서 가장 임팩트 있는 걸 골라서 더 발전시켜줘"
- "정반대 입장에서 비판해봐"

**꿀팁:** AI가 뽑은 결과에서 "마음에 드는 부분"과 "고치고 싶은 부분"을 나눠서 구체적으로 지시하세요. "좀 이상해"는 도움이 안 됩니다.

## 4. Claude 데스크탑만의 다섯 가지 무기

웹 버전이 아니라 **데스크탑 앱에서만** 빛나는 기능들입니다. 이걸 쓰면 프롬프팅이 훨씬 강력해져요.

### 무기 1. 파일 드래그 앤 드롭

PDF, Word, 이미지, 코드 파일 등을 **대화창에 끌어다 놓기만 하면** 업로드됩니다.

**활용 예시:**
- 계약서 PDF 끌어다 놓고 → "핵심 위험 조항만 찾아줘"
- 엑셀 끌어다 놓고 → "이 데이터로 3가지 인사이트 뽑아줘"
- 스크린샷 찍어서 → "이 화면의 UX 문제점 지적해줘"
- 코드 파일 주고 → "이 함수 리팩토링 방안 제안해줘"

텍스트를 복사-붙여넣기 하지 말고 **파일 그대로** 주세요. 포맷 정보까지 유지됩니다.

### 무기 2. 프로젝트 (Projects)

반복 작업은 프로젝트에 묶어두세요. **공통 지침 + 공통 파일**을 한 번만 세팅하면, 새 대화 열 때마다 Claude가 다 기억합니다.

**프로젝트 활용 시나리오:**
- "우리 회사 브랜드 가이드" 프로젝트 → 가이드 PDF 업로드, "너는 브랜드 가이드를 엄격히 지키는 카피라이터야" 지침. 이제 새 카피 작업마다 여기서 시작.
- "고객 인터뷰 분석" 프로젝트 → 인터뷰 녹취록 5개 업로드, "이 데이터를 기준으로만 답하고 추측 금지" 지침. 매번 새로 업로드할 필요 없음.

### 무기 3. 아티팩트 (Artifacts)

Claude가 글·코드·다이어그램 등을 만들면, **오른쪽 패널에 "작품"처럼 따로 띄워줍니다**. 길이가 긴 결과물은 채팅 안에 섞이지 않고 여기 나타나요.

**아티팩트를 잘 쓰는 법:**
- "이 내용을 아티팩트로 만들어줘"라고 명시적으로 요청
- 만들어진 아티팩트는 다시 수정 요청 가능: "3번 항목만 바꿔줘"
- 다운로드 또는 복사해서 밖으로 내보내기

글이면 Markdown, 코드면 해당 언어 파일, 다이어그램이면 Mermaid — 각각 맞는 포맷으로 나옵니다.

### 무기 4. 스타일 (Writing Style)

Claude가 답하는 **말투를 사전 설정**할 수 있어요.

- 기본 스타일 (표준)
- Concise (간결하게)
- Explanatory (상세히)
- Formal (격식 있게)
- + 커스텀 스타일: 자기 글 샘플을 주면 그 톤을 학습

마케터라면 **자기 브랜드 톤**을 커스텀 스타일로 저장해두세요. 매번 "친근한 말투로" 쓸 필요 없음.

### 무기 5. MCP (외부 도구 연결) — 맛보기

데스크탑에서 Slack, Google Drive, GitHub 같은 외부 서비스를 연결하면, Claude가 **실제로 그 서비스 안을 돌아다니며** 일해줍니다.

- "내 Gmail에서 이번 주 중요 메일 3개 요약해줘"
- "Slack 마케팅 채널에서 어제 올라온 결정사항 정리해줘"
- "Google Drive의 이 폴더 파일 10개를 분석해서 공통 패턴 찾아줘"

초보자는 일단 **파일 드래그 + 프로젝트 + 아티팩트** 세 개만 익혀도 충분합니다. MCP는 익숙해진 다음에 차근차근.

## 5. 초보자가 자주 하는 실수 7가지

### 실수 1. "잘 해줘"만 쓰기

"좋게", "잘", "예쁘게" 같은 단어는 AI에게 아무 의미 없어요. **구체적으로.**

- 나쁨: "이메일 잘 써줘"
- 좋음: "이메일 써줘. 짧게(150자 이내), 정중하지만 단호하게, 마감일은 이번 주 금요일로 명시"

### 실수 2. 한 번에 여러 가지 지시

"요약하고 번역하고 3가지 개선안도 제시해줘"보다는 **한 번에 한 가지**씩 해서 대화를 이어가는 게 품질이 높습니다.

### 실수 3. AI 답변을 그대로 믿기

Claude도 **할루시네이션**(그럴듯한 거짓말)을 합니다. 특히 숫자·이름·인용·법조문은 반드시 직접 검증하세요.

### 실수 4. 대화 맥락 안 잡고 새 대화에서 다시 시작

앞 대화의 맥락을 새 대화는 모릅니다. 중요한 작업은 **같은 대화 안에서** 계속 이어가거나, 프로젝트로 묶으세요.

### 실수 5. 길이 제한을 안 걸기

"써줘"만 하면 AI는 길게 뽑습니다. 원하는 분량을 미리 지정하세요. "200자", "불릿 5개", "한 페이지 이내".

### 실수 6. 예시 없이 새 형식 요구

AI가 처음 보는 형식으로 써달라면 헤맵니다. **예시 하나만 보여주면** 바로 따라해요.

### 실수 7. 실패한 프롬프트를 그대로 재시도

같은 말 반복해서 결과가 바뀌길 기대하지 말고, **프롬프트 자체를 바꿔야** 합니다. 부족한 맥락을 찾아 추가.

- 4개는 중간 정도 대담한 것
- 3개는 완전 미친 것

글:
\{글 내용\}
