# LLM은 어떻게 학습할까?
## 머신러닝 → 딥러닝 → Transformer → ChatGPT까지의 전체 여정

> 앞의 두 문서(용어 사전·Transformer 해설)의 후속편입니다.

> 중요한 건 **큰 그림**이에요. 이 문서를 다 읽으면 "ChatGPT는 어떻게 만들어지나?"라는 질문에 맥락 있게 답할 수 있습니다.

## 1. 이 문서를 읽기 전에 — 큰 지도 한 장

ChatGPT 같은 LLM이 만들어지는 전 과정을 한 줄로 요약하면:

> **인터넷 전체를 읽히고 → 대화법을 가르치고 → 사람 취향에 맞추고 → 필요하면 추론까지 훈련시켜서 → 세상에 내보낸다.**

이걸 더 풀면 이렇습니다:

```
[원재료: 인터넷·책·코드 수 테라바이트]
            ↓
[1단계] 사전학습 (Pre-training)         — 수개월, 수백억~수천억 원
            ↓
[2단계] 감독 미세조정 (SFT)              — 수일~수주, 수억~수십억 원
            ↓
[3단계] 정렬 (RLHF/DPO)                 — 수일~수주
            ↓
[4단계] 추론 훈련 (선택)                 — o1, Claude Thinking 등
            ↓
[5단계] 안전 점검·서빙·배포
            ↓
[완성된 ChatGPT/Claude/Gemini]
```

이 단계들 각각이 뭔지, 왜 필요한지를 차근차근 풀어갑니다. 그 전에 "학습"이라는 말의 진짜 의미부터.

## 2. 머신러닝: 기계가 "배운다"는 게 뭔데?

### 2.1 전통적인 프로그래밍 vs 머신러닝

옛날 방식(전통 프로그래밍)으로 "스팸 메일 필터"를 만든다고 해봅시다.

- 규칙 1: "100만 달러"라는 단어 있으면 스팸
- 규칙 2: "Viagra" 단어 있으면 스팸
- 규칙 3: 링크가 5개 이상이면 스팸
- 규칙 4: ...

이렇게 **사람이 규칙을 일일이 적어줍니다**. 문제는? 스팸은 계속 진화해서 규칙을 끝없이 추가해야 해요. 그리고 "이건 스팸 같지만 뭔가 미묘한…" 같은 애매한 건 규칙으로 못 잡아요.

### 2.2 머신러닝의 발상 전환

> "규칙은 **우리가 가르쳐주지 말고**, 컴퓨터에게 **수많은 예시**를 보여주자. 그러면 컴퓨터가 스스로 패턴을 찾아낼 거야."

**비유로 보면:**

아이에게 고양이를 가르치는 두 가지 방법이 있어요.

- 방식 A (전통 프로그래밍): "고양이는 귀가 뾰족하고, 수염이 있고, 눈이 동그랗고, 털이 있고…" 말로 끝없이 설명.
- 방식 B (머신러닝): 고양이 사진 10,000장을 보여주면서 "이거 다 고양이야" 하고, 개 사진 10,000장 보여주면서 "이건 개야". 아이는 직접 본 걸로 **패턴을 내면화**합니다.

사람이 살면서 배우는 방식이 거의 B예요. 머신러닝은 컴퓨터에게 B 방식을 시키는 거죠.

### 2.3 머신러닝의 공식 정의 (부담 없이)

"예시(데이터)를 보여주면서, 컴퓨터가 스스로 **예측 규칙**을 찾게 하는 기술"

이때 "예측 규칙"은 간단한 수식일 수도 있고, 엄청 복잡한 구조일 수도 있어요. 딥러닝은 "엄청 복잡한 구조"를 쓰는 머신러닝의 한 갈래입니다.

### 2.4 학습에 필요한 세 가지

머신러닝이든 딥러닝이든 공통적으로 3종 세트가 있어요.

1. **데이터**: 학습에 쓸 예시들. 많을수록, 깨끗할수록 좋음.
2. **모델**: 패턴을 담을 그릇. 수식 또는 신경망.
3. **학습 방법**: 모델이 데이터를 보고 어떻게 개선할지(아래에서 설명).

이 세 개가 있어야 "학습"이 됩니다. LLM도 똑같아요. 차이는 **규모**.

## 3. 딥러닝: 뇌를 흉내 낸 학습 방식

### 3.1 신경망이 뭐야?

딥러닝의 핵심 도구는 **인공 신경망(Neural Network)** 입니다. 사람의 뇌를 아주 거칠게 흉내 낸 구조예요.

**비유로 보면:**

공장의 조립 라인을 떠올리세요.

- 1번 라인: 원재료 받아서 가볍게 가공
- 2번 라인: 그 결과를 받아서 다시 가공
- 3번 라인: 더 복잡한 형태로
- ...
- 마지막 라인: 완제품

**신경망의 각 "층"은 그 조립 라인의 한 단계**예요. 입력이 여러 층을 지나면서 점점 더 의미 있는 정보로 변합니다.

### 3.2 "뉴런"이라는 작은 계산기

각 층에는 **뉴런(노드)**이라는 작은 계산기가 수백~수만 개 있어요. 각 뉴런이 하는 일은 단순합니다.

> "받은 값들에 **가중치**를 곱해서 더하고, **활성화 함수**를 씌워서 내보낸다."

너무 수학적이면 이렇게 생각하세요. 뉴런은 **"여러 방향에서 들어온 정보를 가중 평균하는 믹서"**입니다. 어떤 정보를 얼마나 중요하게 볼지(=가중치)가 학습의 대상.

### 3.3 "깊다(deep)"는 게 왜 중요해?

층을 쌓을수록, 모델이 **복잡한 패턴**을 학습할 수 있어요.

이미지 인식을 예로 들면:
- 1층: 선과 에지만 인식
- 2층: 선들이 모여 만든 모서리, 곡선
- 3층: 모서리가 모여 만든 눈, 코, 귀
- 4층: 눈·코·귀가 모여 만든 "얼굴"
- ...

얕은 모델로는 "선" 수준밖에 못 보지만, 깊어지면 "얼굴", "표정", "감정"까지 인식 가능. **딥러닝의 "deep"은 이 "깊이"를 말합니다.**

LLM의 Transformer도 보통 **수십~수백 층**으로 쌓여 있어요.

## 4. 신경망이 "배우는" 실제 과정 — 오차와 반복

여기가 중요합니다. "학습한다"는 게 구체적으로 뭘 하는 건지.

### 4.1 학습 = 가중치 조정

앞에서 뉴런이 "가중치를 곱해서 더한다"고 했죠. 모델 안에 **가중치가 수억~수조 개** 있어요. 학습은 이 **가중치들을 조금씩 바꿔가며** 정답에 가까워지게 만드는 과정입니다.

**비유:** 라디오 손잡이 1조 개를 조금씩 돌려가며 깨끗한 방송에 맞추는 것. 아무도 손으로 못 하니까, **자동으로 돌리는 알고리즘**이 필요해요.

### 4.2 학습 한 사이클이 어떻게 돌아가는가

한 번의 학습 사이클은 대략 4단계입니다.

**[1단계] 입력 → 예측(Forward Pass)**

데이터를 모델에 넣고 답을 뽑아봅니다. "고양이 사진"을 넣었는데 모델이 "개일 확률 70%"라고 답했다고 해봐요. 아직 덜 배운 상태라 틀렸죠.

**[2단계] 정답과 비교 → 오차 계산(Loss)**

실제 답("고양이")과 모델의 예측("개 70%")을 비교해서 **얼마나 틀렸나**를 숫자로 계산합니다. 이 숫자를 **Loss(손실)** 라고 불러요.

**비유:** 시험 채점. "3번 문제는 얼마나 틀렸지?"를 점수로 매기는 단계.

**[3단계] 책임 분배 → 역전파(Backpropagation)**

"이 오차가 어디서 생긴 거지? 어떤 가중치를 얼마나 바꿔야 덜 틀릴까?"를 역방향으로 계산해요.

**비유:** 축구 경기 후 감독이 "이 실점은 수비수 A가 30%, 골키퍼가 20%, 미드필더 B가 10% 책임이다"를 배분하는 것. 각 선수(가중치)에게 얼마나 개선해야 할지 지정.

이게 힌튼 교수가 1980년대에 대중화시킨 **역전파(Backpropagation)** 알고리즘입니다. 이 알고리즘이 없으면 딥러닝은 아예 불가능해요.

**[4단계] 가중치 업데이트**

배분된 책임만큼 가중치를 조금씩 바꿉니다. 방향과 크기를 결정하는 게 **Optimizer**(예: Adam, SGD).

**비유:** 선수들에게 "너는 이쪽으로, 너는 저쪽으로 한 걸음씩 위치 바꿔"라고 지시.

### 4.3 이걸 "수억 번" 반복

한 번 돌았다고 똑똑해지지 않아요. **데이터 샘플 하나에 대해 한 번, 그걸 수조 번** 반복합니다. 점점 Loss가 줄어들면서, 모델이 정답에 가까워져요.

**LLM 학습의 본질도 이겁니다:**

> "인터넷의 다음 단어 맞추기 문제를 **수조 번** 풀면서, 틀릴 때마다 가중치를 조금씩 고친다."

이게 사전학습의 전부예요.

### 4.4 "학습률(Learning Rate)"이라는 중요한 숫자

한 번 업데이트할 때 **얼마나 크게 바꿀지**가 학습률. 너무 크면 정답 주변을 빗겨가고, 너무 작으면 영원히 안 도달해요. 비유로 치면 **"한 걸음의 보폭"**. 실전에서 가장 많이 튜닝하는 숫자.

## 5. Transformer가 학습 대상이 될 때

자, 앞에서 4장까지 배운 "딥러닝 학습 방식"을, 이제 **Transformer 구조**에 적용해봅시다.

### 5.1 Transformer는 그냥 "신경망의 한 형태"다

앞 문서에서 Transformer가 인코더/디코더, Self-Attention, Multi-Head 등으로 구성됐다고 했죠. 이 모든 게 결국 **숫자로 된 행렬 연산**이에요. 즉, 안에 가중치(파라미터)가 잔뜩 있어요.

- Query 변환 행렬 → 가중치 덩어리
- Key 변환 행렬 → 가중치 덩어리
- Value 변환 행렬 → 가중치 덩어리
- FFN(Feed-Forward) 행렬 → 가중치 덩어리
- Positional Encoding → 경우에 따라 학습 대상

GPT-4의 파라미터가 1조 개 언저리인데, **이게 다 학습되는 숫자들**이에요. 전부 Transformer 안에 들어있는 가중치.

### 5.2 Transformer의 "학습 과제"가 뭐냐

LLM의 학습 과제는 한 문장으로 말하면:

> **"다음 단어(토큰) 맞추기."**

예시:
- 입력: "철수는 어제 시장에서 사과를"
- 정답: "샀다"
- 모델 예측: "만들었다" (60%), "샀다" (25%), "먹었다" (10%) ...

여기서 모델이 "만들었다"를 1등으로 뽑았으니 틀렸어요. Loss가 생깁니다. 역전파 → 가중치 조정 → 다시 예측 → ...

**인터넷·책·코드의 모든 문장에 대해 이걸 시킵니다.** 한 문장에서 단어가 100개면, 100개 자리에서 "다음 단어 맞추기" 문제가 뽑혀요. 수조 개의 문제를 풀면서 모델이 언어를 내면화합니다.

### 5.3 그래서 Transformer가 왜 학습에 유리하냐

기존 RNN은 단어를 **순차적으로** 처리해서, 가중치 업데이트도 순서대로 해야 했어요. GPU의 병렬 연산을 제대로 못 씁니다.

Transformer는 한 문장의 모든 단어를 **동시에** 처리. GPU 수천 장이 병렬로 뛸 수 있어요. 그래서 **같은 시간에 훨씬 많은 문장을 학습**할 수 있습니다.

> 이 속도 차이가 "LLM이 갑자기 똑똑해진" 결정적 이유.

2017년 Transformer 등장 이전엔 이 속도로 학습이 안 돼서, 모델을 크게 만들면 훈련 비용이 감당 안 됐어요. Transformer가 그 벽을 뚫은 겁니다.

### 5.4 앞 문서와의 연결 포인트

- **Self-Attention**: 이 안의 Q/K/V 변환 가중치들이 학습 대상.
- **Multi-Head**: 각 Head가 자기만의 Q/K/V 가중치 세트를 가짐. 8개 Head면 8배.
- **FFN**: 변환 행렬이 학습 대상. Transformer 파라미터 대부분은 실제로 FFN에 있어요.
- **Positional Encoding**: 고정된 공식(sin/cos) 또는 학습되는 행렬.
- **Residual + LayerNorm**: 학습 안정성을 돕는 장치. 이게 없으면 깊은 모델 학습이 망가짐.

이 모든 부품이, 앞에서 배운 "예측 → 오차 → 역전파 → 업데이트" 사이클을 통해 동시에 조정됩니다.

## 6. LLM 학습의 전체 여정 — 4+1 단계 파이프라인

자, 이제 진짜 LLM 학습 파이프라인입니다. GPT-4, Claude, Gemini 모두 대동소이한 여정을 거쳐요. 한 단계씩 풀어봅니다.

### Step 0. 데이터 수집 및 전처리

**뭐하나:** 인터넷·책·코드·논문 등에서 텍스트를 모읍니다.

**얼마나:** GPT-4급 모델은 **수 조(trillion) 토큰** 수집. 토큰으로 환산하면 위키피디아 영문판 전체가 대략 30억 토큰인데, 그걸 **수천 배** 모으는 겁니다.

**데이터 출처 예시:**
- Common Crawl (웹 크롤링 데이터) — 대량
- Wikipedia
- 책 데이터셋 (Books1, Books2)
- GitHub 코드
- 학술 논문 (ArXiv, PubMed)
- 레딧·포럼 글

**전처리가 핵심:**
- **품질 필터링**: 스팸·광고·오타 천지인 글은 제외. 품질 높은 문서에 가중치 더 줌.
- **중복 제거**: 같은 문서가 여러 번 섞이면 모델이 그쪽으로 편향됨.
- **유해 컨텐츠 제거**: 아동 학대, 극단 폭력 등 법적·윤리적 금지 영역.
- **토큰화**: 수집한 텍스트를 토큰(숫자 ID)으로 변환.

**비유:** 요리하기 전에 재료 씻고, 상한 것 버리고, 크기별로 다듬는 단계. 요리가 잘 되려면 재료 손질이 절반. LLM도 똑같아요. **"데이터가 모델의 천장"**이라는 말이 업계의 진리.

---

### Step 1. 사전학습 (Pre-training) — 가장 오래, 가장 비쌈

**뭐하나:** 앞에서 설명한 "다음 단어 맞추기" 과제를, **수집한 모든 텍스트에 대해** 수행. 이게 모델 학습의 **99% 시간과 비용**을 차지합니다.

**구체적으로:**
- 텍스트에서 무작위 위치를 잘라서 "여기까지 주고 다음 단어 맞히기" 문제를 뽑아요.
- 모델이 답을 예측 → Loss 계산 → 역전파 → 가중치 조정.
- 이걸 **수조 번** 반복.

**한 번 학습하는 데 걸리는 시간:**
- GPT-3 (1750억 파라미터): GPU 약 1만 장으로 **수개월**
- GPT-4 (약 1조 파라미터 추정): GPU 수만 장으로 **3~6개월**
- 훈련 중 전기만 수백억 원, 장비까지 합치면 수천억 원

**결과물:** **Base Model**. 이 모델은 똑똑한데 **말을 안 들어요**. 그냥 "다음 단어 맞추기"만 훈련받아서, 질문하면 답 안 하고 관련 글만 이어 씁니다.

**예시 (Base Model):**
- 입력: "대한민국의 수도는?"
- 출력: "대한민국의 수도는 어디인가요? 이 질문은 초등학교 사회 시험에 자주 나옵니다. 정답은 서울이고..." (질문에 답 안 하고 기사 써버림)

이 상태로는 쓸 수 없어요. 그래서 다음 단계가 필요.

**비유:** 대학원생이 책 수천 권 읽고 모든 분야에 대해 썰 풀 수 있지만, **누가 물어봐도 자기 할 말만** 하는 상태. 이제 대화 예절을 가르쳐야 돼요.

---

### Step 2. 감독 미세조정 (SFT · Supervised Fine-Tuning)

**정식 명칭:** Supervised Fine-Tuning. 또는 Instruction Tuning (인스트럭션 튜닝).

**뭐하나:** "질문 → 좋은 답변" 쌍을 **수만~수십만 개** 준비해서, Base Model에게 "이런 식으로 답하렴"을 가르칩니다.

**데이터 예시:**

```
[질문] 대한민국의 수도는?
[답변] 대한민국의 수도는 서울입니다.

[질문] 프로그래밍 입문자에게 추천할 언어는?
[답변] 파이썬을 추천합니다. 이유는 세 가지예요. 첫째, 문법이 간결...

[질문] 햄스터 키우는 법 알려줘.
[답변] 햄스터를 잘 키우려면 아래 사항을 꼭 지키세요. 1. 케이지는 최소...
```

**누가 이 데이터를 만드나:**
- **사람(어노테이터)** 이 직접 씁니다. 한 명당 수십~수백 개.
- 회사들은 수백~수천 명을 고용해서 몇 달에 걸쳐 만듦.
- 요즘은 "AI가 AI를 가르치기(Synthetic Data)"도 섞어요.

**학습 방식:** 앞의 사전학습과 똑같아요. "질문+답변" 텍스트에서 "다음 단어 맞추기"를 시킵니다. 다만 Base Model은 이미 많이 알아서, **수천~수만 번 반복**이면 충분. 사전학습의 0.1~1% 시간/비용.

**결과물:** 이제 질문을 받으면 답변 형식으로 응답합니다.

**비유:** 책만 잔뜩 읽은 대학원생에게, **"누가 물어보면 친절하게 요점부터 답하고, 필요하면 예시를 들어"** 라는 예절 교육. 과외 선생님 연수 같은 거.

---

### Step 3. 정렬 (Alignment) — RLHF / DPO

**왜 필요한가:** SFT까지 끝낸 모델도 아직 문제가 있어요.

- 때때로 **거짓말**을 합니다 (할루시네이션).
- 때때로 **무례**해요.
- 때때로 **위험한 답**(폭탄 만드는 법 등)을 해주려 합니다.
- 답변이 **길거나, 짧거나, 애매**해요.

SFT 데이터 수만 개로는 이걸 다 잡기 어렵습니다. 그래서 더 영리한 방식이 등장.

#### 3-1. RLHF (인간 피드백 기반 강화학습)

**뭐하나:**
1. 모델이 같은 질문에 대해 답을 **2~4개 만들어줘**.
2. 사람이 "A > B > D > C" 식으로 순위를 매겨.
3. 이 순위 데이터로 **보상 모델(Reward Model)** 을 따로 훈련. 이건 "얼마나 좋은 답인지 점수 매기는 모델".
4. 이제 원래 LLM이 답을 만들면 → 보상 모델이 점수 → 점수 높게 나오는 방향으로 LLM 가중치 조정.

**비유:** 아이가 그림 두 장을 가져오면 "왼쪽이 더 예쁘네"라고 피드백 주는 걸 **수백만 번** 반복. 아이가 엄마 취향을 내면화합니다. **ChatGPT가 정중하게 답하는 말투도 RLHF 산물.**

**장점:** 섬세한 취향까지 학습 가능. 안전성 향상.
**단점:** 복잡하고 불안정. 튜닝이 까다로움.

#### 3-2. DPO (Direct Preference Optimization)

2023년 등장한 더 간단한 방법. 보상 모델 따로 안 만들고, **"사람이 뽑은 승자/패자 답변 쌍"** 으로 바로 모델을 학습. 요즘 많은 회사가 이걸 씁니다. 효과는 RLHF와 비슷하거나 더 안정적.

**결과물:** 드디어 **배포 가능한 모델**. 예의 바르고, 안전하고, 유용한 답을 합니다. 이 상태가 ChatGPT·Claude·Gemini의 "기본 상태".

---

### Step 4. (선택) 추론 훈련 — o1, Claude Thinking 방식

2024년 후반부터 등장한 **새로운 단계**. 모든 모델이 하는 건 아니지만, 고성능 모델들은 대부분 추가합니다.

**뭐하나:** 모델이 답하기 전에 **"속으로 길게 생각"** 하는 습관을 학습시켜요. "생각의 연쇄(Chain of Thought)"를 늘리는 훈련.

**방식:**
- 수학·코딩·논리 문제처럼 **정답이 명확한** 문제를 많이 줌.
- 모델이 답을 생성하는데, 그 중간에 **긴 풀이 과정을 쓰게** 유도.
- 풀이 과정이 맞는 방향이면 보상, 틀리면 벌. 이걸 강화학습으로 훈련.

**결과물:**
- OpenAI o1/o3, DeepSeek R1, Claude 3.7 Extended Thinking, Gemini Thinking 같은 **추론 특화 모델**.
- 수학·프로그래밍·과학 문제에서 일반 모델 대비 훨씬 강함. 대신 **느리고 비쌈**.

**비유:** 시험 볼 때 "답부터 찍지 말고, 풀이 과정 꼭 적어"를 몸에 배게 훈련시키는 단계.

---

### Step 5. 안전 점검·서빙·배포

**뭐하나:**
1. **Red Team**: 내부/외부 전문가가 모델을 **일부러 공격**해봄. "폭탄 만드는 법 답해?" "인종차별 유도하면?" 등 극단 케이스 테스트.
2. **평가**: MMLU, HumanEval, SWE-Bench 등 **벤치마크** 돌려서 성능 측정.
3. **최적화**: 모델을 더 가볍게 만들기. 양자화(Quantization), 증류(Distillation), KV 캐시 최적화 등.
4. **서빙 인프라 구축**: GPU 클러스터 + 로드 밸런서 + API 서버 세팅.
5. **배포**: API 또는 서비스로 공개.
6. **모니터링**: 배포 후에도 문제 케이스 수집하고, 다음 버전에 반영.

**비유:** 완성된 요리를 **레스토랑 메뉴로 올리기 전** 단계. 시식, 가격 책정, 주방 세팅, 서빙 트레이닝.

---

## 7. 실제 스케일 — GPT-4급 모델은 얼마나 큰 일인가

숫자로 감이 안 잡히니 실제 사례로 봅시다. 추정치/공개 정보 기준입니다.

### 데이터

- GPT-3 (2020): 약 **3000억 토큰**
- GPT-4 (2023, 추정): **1조+ 토큰**
- Llama 3 (2024): **15조 토큰**
- 최신 프론티어 모델: **수십조 토큰**

"15조 토큰"이 얼마냐면, 위키피디아 영문판의 약 **5000배**. 평범한 사람이 평생 읽을 수 있는 양의 수만 배.

### 파라미터(가중치 개수)

- GPT-3: 1750억 개
- GPT-4: 1조+ 개 (정확한 숫자 미공개)
- Claude·Gemini 최신: 수천억 ~ 1조+ 범위

### 학습에 쓰이는 GPU

- **H100 GPU** (2024 주력): 장당 약 3~5천만 원
- GPT-4 훈련: 약 25,000장 동원 추정
- **GPU만 1조 원 규모**

### 학습 시간과 전기

- 훈련 기간: 3~6개월 연속
- 소비 전력: 수십 MW 급 (중소도시 한 곳과 맞먹음)
- 전기료만 **수백억 원**

### 총 학습 비용 (추정)

- GPT-4: **1억~2억 달러 (수천억 원)**
- 차세대 모델: **5억~10억 달러** 예상
- 훈련 데이터 만드는 사람 인건비도 여기 포함

### 사람은 얼마나 붙나

- AI 연구자·엔지니어: 수백 명
- 데이터 어노테이터: 수천 명 (외주 포함)
- Red Team, 안전성 연구: 수십~수백 명
- 인프라 엔지니어: 수십 명

**왜 이렇게 비싼가:** 단순히 컴퓨터를 돌린다고 되는 게 아니에요. 데이터를 어떻게 섞고, 언제 학습률을 바꾸고, 어느 시점에 체크포인트를 찍고, 어떤 기법으로 안정화하는지 — **노하우 자체가 천억 원짜리**. 그래서 프론티어 LLM을 만들 수 있는 회사가 전 세계에 **10여 곳**밖에 안 됩니다.

## 8. 전체 지도 다시 보기

여기까지 따라오셨으면, 이제 "LLM이 어떻게 똑똑해지는가"의 큰 그림이 머리에 그려졌을 거예요. 한 번 더 정리.

### 개념 계층

```
AI
 └─ 머신러닝 (예시로 배움)
     └─ 딥러닝 (뇌 흉내 낸 신경망)
         └─ Transformer (딥러닝의 한 구조)
             └─ LLM (Transformer로 만든 언어 모델)
                 └─ ChatGPT/Claude/Gemini (RLHF까지 거친 완성품)
```

### 학습의 원리 (공통)

1. 데이터 보여주기 → 2. 예측시키기 → 3. 오차 계산 → 4. 가중치 조정 → 5. 반복

### LLM 학습 파이프라인 (순서)

1. **데이터 수집·전처리** — 인터넷 + 책 + 코드, 수조 토큰
2. **사전학습 (Pre-training)** — 다음 단어 맞추기, 몇 달·수천억 원
3. **감독 미세조정 (SFT)** — "이렇게 답하렴" 가르치기
4. **정렬 (RLHF/DPO)** — 사람 취향·안전성 맞추기
5. **(선택) 추론 훈련** — 속으로 길게 생각하는 습관
6. **안전·배포·서빙**

### Transformer와의 연결

- Transformer는 **학습되는 그릇 (모델 구조)**.
- 그릇 안의 **가중치들이 학습 대상**.
- Self-Attention·Multi-Head·FFN 같은 부품들의 가중치가, 위 파이프라인에서 **계속 조정**되는 겁니다.
- "GPT는 Transformer의 디코더만 써서 만든 LLM" — 앞 문서 내용이 여기로 이어져요.

### 힌튼의 위치

- **역전파(Backpropagation)** → 4장의 학습 알고리즘의 토대.
- 힌튼은 Transformer 저자 아님. 하지만 Transformer가 학습되는 방식 자체의 **토대를 만든 사람**.

## 마지막으로

뉴스에서 "xx 회사가 새 LLM을 공개했다"가 나올 때, 이제는 이렇게 읽힐 거예요:

- 데이터 얼마나 모았을까? (품질 vs 양)
- 사전학습에 얼마나 썼을까? (파라미터 x 토큰 = 비용 감)
- SFT·RLHF는 제대로 돌렸을까? (답변 품질·안전성)
- 추론 훈련도 했을까? (수학·코딩 성능)
- 배포 방식은? (API? 오픈소스? 온디바이스?)

"AI가 똑똑해진다"라는 뭉툭한 말 대신, 각 단계의 구체적 움직임이 보이기 시작합니다. 그게 이 문서의 목표였어요.
