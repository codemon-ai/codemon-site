# 하이테커 · 복사해서 쓰는 실습 프롬프트

대괄호 내용을 자신의 정보로 바꿉니다. 단계별로 결과를 검토하고 다음 프롬프트로 넘어갑니다. 명령은 실행을 약속하는 문서가 아니라 수강생이 실제 Claude Code에 입력할 교육용 예시입니다. 사전 준비: https://codemon.ai/webinar

## P0 · 실습 환경 점검

```text
현재 작업 폴더의 위치와 파일을 확인해줘.
Claude Code, Node.js, npm, Vercel CLI 사용 가능 여부를 점검해줘.
비밀값은 출력하지 말고 로그인 여부만 확인해줘.
설치된 플러그인과 연결된 MCP 서버 목록을 알려줘.
부족한 준비는 내 운영체제에 맞춰 한 단계씩 안내해줘.
아직 파일을 수정하거나 배포하지 마.
```

## P1 · 내 첫 스킬 만들기

```text
이번 포트폴리오 제작에서 반복 사용할 품질 점검 절차를 스킬로 만들어줘.
.claude/skills/portfolio-check/SKILL.md에 저장해줘.
name은 portfolio-check, description에는 사용할 상황을 명시해줘.
점검 항목은 모바일 가로 넘침, 키보드 조작, 실제 링크, 예시 표시,
비밀값 노출, 공개할 파일 범위야. 자동 배포 동작은 넣지 마.
검증 결과는 통과 / 실패 / 미확인으로 구분하고 근거를 적게 해줘.
브라우저 도구가 있으면 직접 확인하고, 없으면 사용자가 확인할 체크리스트를 출력하게 해줘.
```

## P2 · 브레인스토밍으로 아이디에이션

```text
/superpowers:brainstorming
나는 [직업/관심 분야]의 한 페이지 포트폴리오 사이트를 만들고 싶어.
방문자는 [채용 담당자/잠재 고객]이고, 원하는 행동은 [사례 확인 후 이메일 연락]이야.
오늘 60분 안에 HTML/CSS/JavaScript 정적 사이트로 Vercel에 배포할 거야.
로그인, 결제, DB, 문의 저장 폼은 이번 범위에서 제외해줘.
질문은 한 번에 하나씩 해줘. 결정이 끝나면 화면 구성, 사례 3개의 틀,
완료 기준 5개를 docs/plans/portfolio-design.md에 정리해줘. 아직 구현하지 마.
```

## P3 · 포트폴리오 한방 프롬프트 (로컬 확인까지)

```text
docs/plans/portfolio-design.md대로 site/ 폴더에 포트폴리오를 구현해줘.
index.html, styles.css, app.js로 구성하고 외부 라이브러리는 사용하지 마.
화면은 소개 → 작업 사례 3개 → 작업 방식 → 연락 순서야.
사례는 문제 / 내가 한 일 / 결과 형식으로, 카테고리 필터와 이메일 복사 버튼을 넣어줘.
허구의 경력·고객·성과 수치를 만들지 말고, 미제공 내용은 [예시]라고 표시해줘.
필수 이미지가 없으면 CSS 도형으로 구성해줘.
구현이 끝나면 site/에서 로컬 서버를 실행하고, 실제 접속 주소를 알려줘.
/portfolio-check로 자체 점검하고 결과를 check.md에 남겨줘.
확인이 끝날 때까지 나에게 질문하지 말고 끝까지 진행해줘. 아직 배포하지 마.
```

## P4 · 브레인스토밍 결과를 아티팩트로

```text
아래는 내 포트폴리오 사이트의 설계 문서야.
방문자 여정(첫 화면 → 사례 → 연락)과 화면 구성을 한눈에 보이는
인터랙티브 아티팩트로 시각화해줘.
섹션을 클릭하면 그 섹션의 목적과 완료 기준이 펼쳐지게 해줘.
문서에 없는 내용은 추가하지 말고, 예시 표시는 그대로 유지해줘.

[docs/plans/portfolio-design.md 내용 붙여넣기]
```

## P5 · 관찰한 문제로 한 번 수정

```text
현재 화면에서 [휴대폰 너비에서 제목이 잘림]을 확인했어.
기대 결과는 [390px 너비에서 가로 스크롤 없이 제목 전체가 보임]이야.
재현 조건은 [브라우저/너비/클릭 순서]이고 실제 결과는 [관찰한 내용]이야.
관련 원인을 찾아 필요한 범위만 수정해줘.
변경 전후를 비교하고 같은 조건으로 다시 확인해줘.
전체 디자인이나 기능을 새로 만들지 마.
```

## P6 · Playwright로 테스트

```text
Playwright MCP로 로컬 서버 주소를 열어 다음을 실제로 확인해줘.
1) 390px 너비에서 가로 스크롤이 없다.
2) 카테고리 필터를 누르면 해당 사례만 남는다.
3) 이메일 복사 버튼을 누르면 복사 완료 표시가 나온다.
4) Tab 키로 버튼과 링크에 순서대로 이동할 수 있다.
각 항목의 스크린샷을 찍고 통과 / 실패 / 미확인과 근거를 check.md에 추가해줘.
브라우저를 실제로 열지 못했으면 통과라고 쓰지 마.
```

## P7 · Vercel 플러그인으로 상태 조회

```text
Vercel MCP로 현재 인증 상태와 접근 가능한 팀을 확인해줘.
내가 지정한 [실습 팀/프로젝트]의 배포 상태를 읽어서 요약해줘.
프로젝트가 없으면 없다고 알려줘. 이 단계에서는 새로 만들지 마.
도구 이름과 실제 조회 결과를 구분해서 보여줘.
연결되지 않았으면 성공했다고 추측하지 말고 /mcp 인증 절차를 안내해줘.
```

## P8 · Preview 배포

```text
check.md의 결과를 먼저 확인해줘.
검증한 site/ 폴더만 Vercel CLI로 Preview 배포해줘.
대상 팀은 [팀 이름], 새 프로젝트 이름은 [고유한 실습 이름]이야.
기존 프로젝트와 연결되는 경우 대상이 맞는지 먼저 알려줘.
정적 사이트 설정으로 배포하고 실제 반환된 URL을 알려줘.
배포 성공 여부와 화면 접속 여부를 나누어 확인해줘.
Production 배포와 도메인 구매는 아직 하지 마.
```

## P9 · Production 공개 및 검증

```text
Preview에서 소개·사례·필터·연락 동작을 확인했어.
같은 Vercel 프로젝트에 현재 site/ 내용을 Production으로 배포해줘.
실제 배포 URL을 알려주고 휴대폰 너비와 로그아웃 상태에서 확인할 항목을 적어줘.
접근 보호가 켜져 있다면 현재 설정을 설명해줘.
공개 성공은 설정과 실제 접속 결과를 확인한 뒤에만 보고해줘.
```

## P10 · (부록) Supabase 확장 설계

```text
포트폴리오의 사례 목록을 Supabase에서 읽는 구조로 확장하고 싶어.
이번에는 공개 사례 조회만 만들고, 방문자 쓰기와 로그인은 제외해줘.
전용 실습 프로젝트에서 webinar_projects 테이블을 사용해줘.
컬럼은 id, title, summary, category, published이고 공개 예시만 저장해줘.
RLS를 켜고 anon/authenticated는 published=true인 행의 SELECT만 허용해줘.
테이블 권한과 RLS 정책을 함께 제시하고 비공개 행과 쓰기 차단 검증도 준비해줘.
SQL은 검토할 파일로 먼저 만들어줘. DB 변경은 아직 실행하지 마.
```

## P11 · (부록) Supabase 데이터 연결

```text
실습용 DB의 SQL과 조회 정책을 확인했어.
공개용 Project URL과 publishable key로 사례 목록을 조회하도록 연결해줘.
브라우저에 secret/service_role 키를 넣지 마.
로딩, 빈 목록, 네트워크 실패 상태를 각각 보여줘.
DB 데이터는 textContent 등 안전한 방식으로 렌더링해줘.
공개 사례는 표시되고 비공개 사례는 숨겨지는지 실제 API 요청으로 확인해줘.
방문자 삽입·수정·삭제가 차단되는지도 확인해줘.
연결 실패를 목업 성공 화면으로 위장하지 말고 실패라고 보여줘.
```
